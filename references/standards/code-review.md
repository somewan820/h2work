# 代码审查与合并准入

开发任务 PR 和发布 PR 在合并前都必须经过独立审查，完成交叉验证和对抗性审查。以关联 issue 的验收目标、PR 描述的职责及本次改动的直接影响为边界，基于证据判断是否可以合并。

## 审查基线与职责

- 提交者完成自查后，由本次主要实现者之外的审查者独立核对；自查不能替代独立审查。
- 审查开始时明确关联 issue、PR 职责、适用的项目规范、目标分支、被审查的提交和完整差异。发布 PR 还需明确所属大需求及发布清单。
- 用 issue 确定应交付的行为与验收标准，用 PR 描述核对实现范围。两者存在影响验收的歧义或冲突时，明确分歧并交需求负责人确认，不自行扩大需求。
- 本次改动直接造成的既有功能回归或契约破坏属于审查范围，不能仅因 PR 描述未列出就忽略；为核实影响，可以读取必要的上下游实现。
- 审查同时遵循 [开发与实现原则](development.md)，不借审查增加未经要求的抽象、防御设计或工程流程。

## 交叉验证与对抗性审查

1. 逐项核对本次 issue 的验收要求、PR 声明与实际实现，确认职责内的交付内容完整且一致。
2. 结合实际代码路径、必要的调用方和测试结果交叉验证，不仅依赖提交者的说明或单一测试结论。
3. 在既定输入、状态和调用约束内，主动寻找能推翻实现正确性的具体反例，优先验证关键业务路径和本次改动直接影响的契约。
4. 对候选问题核实触发条件、预期行为与实际后果；能够执行时使用最小复现或有针对性的测试验证。仅基于代码分析的判断，应给出可核验的路径与约束。

交叉验证和对抗性审查可以在同一轮独立审查中完成。以验收覆盖和证据质量衡量审查，不设最低问题数量，也不因方法名称增加重复审查轮次。

## 审查意见要求

每个需要处理的问题应说明：

- 职责依据：对应的 issue 验收项、PR 职责、明确项目约定或直接受影响的既有契约。
- 触发条件：什么实际可达的输入、状态或执行路径会触发问题。
- 证据与后果：相关代码位置、复现步骤、测试结果或可核验的推导，以及预期与实际行为的差异。
- 处理建议：职责内能够解决问题的最小修正方向。
- 合并影响：属于阻塞项、待验证项，还是可另行跟进的非阻塞项。

相同根因合并反馈。执行过的检查与仅通过阅读得出的判断分别说明；推测不能写成已经证实的缺陷。

## 阻塞与非阻塞意见

以下问题可以阻塞合并，但必须提供对应依据和证据：

- 本次职责内的功能缺失、行为错误或直接回归，导致验收要求或必要契约不成立。
- 本次改动违反适用的强制项目约定，并能说明违反了哪条约定及其实际影响。
- 发布内容与清单不一致、必要依赖缺失，或实际发布组合不满足本次验收要求。

本次必需验收项缺少验证证据时，结论标记为待验证，并明确需要补充什么证据后才能判断通过。

以下内容不阻塞当前 PR：

- 与本次职责及直接影响无关的既有问题，可单独记录或另开 issue。
- 个人命名、排版、代码组织偏好，或仅表达“另一种写法更好”的方案偏好。
- 缺少实际触发依据的未来场景、假设性风险，以及职责之外的重构或防御设计建议。

非阻塞项不作为当前 PR 的必修清单，不要求为了消除所有建议而继续修改。

## 复审与收敛

1. 首轮在既定范围内完整审查，将已核实的问题集中反馈，明确阻塞与非阻塞结论。
2. 提交者逐项修复，或提供契约、代码和测试证据说明问题不成立；审查者据此核对，不以个人方案偏好替代证据。
3. 复审聚焦未解决问题、新增修改及其直接影响。已解决且未被后续修改影响的问题保持关闭；只有新证据或新的直接回归才重新打开。
4. 代码、合并基线或发布清单变化后，核对变化及受影响范围，更新审查结论所对应的提交与验证结果。
5. 反复争议而没有新证据时，归纳验收依据、双方证据和具体分歧，由需求负责人裁定，避免反复改写或追加无关要求。

## 发布 PR 的审查范围

重点核对发布清单、任务归属、必要依赖、cherry-pick 冲突处理及实际发布组合。已有任务的审查结论可以作为证据，但不能替代本次发布组合的独立核对。

已通过审查且未受本次组合影响的任务实现，不重新提出与发布职责无关的设计或风格要求。

## 审查结论与合并条件

- 本次职责与验收要求已覆盖，交叉验证和对抗性审查完成，没有未解决的有效阻塞项或必需验收的待验证项。
- 审查结论记录对应提交、审查范围、实际检查方式和结果。非阻塞建议与通过条件分开；满足审查条件即可给出通过结论，允许审查未发现问题。
- 审查结论与构建、测试等检查结果分别记录。审查通过时，仍可存在未完成的独立检查，不能据此判定已经满足全部合并条件；检查通过也不能替代独立审查。
- 最终合并要求独立审查通过，并按 [合并前检查规范](pre-merge-checks.md) 确认所有适用必过项均满足要求，两者均对应最终准备合并的代码。
